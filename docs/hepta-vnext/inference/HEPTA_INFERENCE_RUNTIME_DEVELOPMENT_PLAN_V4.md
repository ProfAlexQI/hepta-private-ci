## 1. Mission and non-goals

Deliver an owner-local, fail-closed inference subsystem that:

1. isolates model execution from Hepta Memory, KG, product writers, route/fleet state,
   promotion, release, and remote inference;
2. bounds connections, queueing, inflight/running work, memory, disk, deadlines, output,
   receipts, and child-process I/O;
3. executes an exact digest-bound local model in an isolated worker;
4. can drive explicitly configured Ollama and LM Studio adapters behind the same daemon
   boundary without implicit downloads, redirects, proxies, or silent fallback;
5. records exact-head, assigned-runner, non-empty evidence without persisting raw prompts,
   raw generated text, capabilities, or worker nonces;
6. enters the product first through an opt-in, non-authoritative shadow bridge;
7. becomes promotable only after exact-device evidence and independent operator acceptance.

Contracts, state machines, fixtures, or workflow source do not prove real provider, real
model, real device, product-shadow, operator, promotion, or release execution.

## 3. Canonical truth and evidence rules

The canonical pointer names this plan plus the V4 current status, implementation status,
stage matrix, blocker ledger, evidence contract, runbook, threat model, and test matrix.
Static documents bind the planning base rather than trying to contain their own future
commit SHA. Exact candidate head/tree, `Cargo.lock` digest, workflow/run/job identity,
runner identity, toolchain, artifacts, and results are generated by CI.

Historical receipts are immutable. Descendant gates validate ancestry, exact schemas where
historically applicable, source markers, and artifact digests; they never require an old
matrix to acquire new fields retroactively.

A required stage may advance only when its receipt:

- names exact repository, head, tree, workflow, run, job, runner OS/architecture, and toolchain;
- contains executed steps and rejects `steps=[]`, `runner_id=0`, cancellation, and skip;
- binds every model, runtime, tokenizer, template, helper, device, policy, and budget by digest;
- states all authority bits;
- is consumed successfully by the single V4 aggregate.

Evidence classes are non-substitutable:

| Class | Proof |
|---|---|
| `E0` | source contracts, build graph, tests, closed authority |
| `E1` | deterministic isolated child process, IPC, crash, timeout, ACK, kill |
| `E2` | real exact-tuple Ollama/LM Studio behavior |
| `E3` | real native runtime and GGUF-generated tokens |
| `E4` | exact-device safety/performance/soak |
| `E5` | real product requests through non-authoritative shadow route |
| `E6` | acceptance by a non-authoring operator |
| `E7` | separately authorized promotion/release |

`E0 != E1 != E2 != E3 != E4 != E5 != E6 != E7`.

## 4. Target architecture

```text
CLI / TUI / Hepta component
        |
        | public owner-local API: handshake, admit, observe, cancel-own, receipt-own
        v
hepta-inferd
  - peer identity + daemon session
  - daemon-minted request capability
  - policy + exact model tuple registry
  - queue/inflight/running/deadline/device admission
  - scheduler + input/KV/prefix leases
  - durable receipt index, recovery, TTL, compaction
        |
        +---------------- private authenticated worker channel ----------------+
        |                                                                      |
        v                                                                      v
provider worker                                                        native worker host
  Ollama / LM Studio                                                    isolated process
  pinned loopback IP                                                    worker-session nonce
  no redirect/proxy/download                                            stable backend ABI
  strict JSON/SSE                                                       pinned llama.cpp
  explicit cancel classification                                        exact GGUF tuple
        |                                                                      |
        +---------------- bounded token/control events ------------------------+
                                       |
                                       v
                           digest-bound terminal receipt
                                       |
                                       v
                         opt-in product shadow bridge
```

Same UID is necessary but insufficient. Public, worker, and operator protocols are typed
and separated. Public clients cannot encode `Start`, `Token`, `Complete`, worker health,
model registration, drain, or restart. Privileged channels require daemon-created session
nonces and role-specific capabilities.

Every accepted request and worker event is fenced by tenant/workspace/agent/task identity,
request ID, agent/request/cancel/backend generations, owner session, request capability
digest, worker-session nonce, exact model tuple digest, policy digest, resource budget,
deadline, and strictly increasing event sequence.

A routable model tuple binds provider/backend identity, runtime build and upstream commit,
model artifact, GGUF metadata, tokenizer, chat template, quantization, context limit,
device profile, license, SBOM, policy, and budget digests. Mutable names/tags are display
metadata only.

## 5. Work packages and acceptance

Required dependency order:

```text
V4-T0 -> V4-T1 -> V4-H1 -> V4-H2 -> V4-R1
      -> V4-P1 -> V4-N1 -> V4-C1 -> V4-S1
      -> V4-PB1 -> V4-D1 -> V4-O1
```

### V4-T0 — Canonical truth and CI convergence (`E0`)

Publish the canonical V4 document set; repair the descendant-unsafe INF-0C gate without
rewriting history; add one exact-head source gate and aggregate; remove references to
nonexistent future files. Acceptance: all active paths exist, workflow source compiles,
historical matrices remain immutable, the source receipt is machine-readable, and any
required non-success/empty/unassigned job makes the aggregate fail.

### V4-T1 — Toolchain and build graph convergence (`E0`)

Keep Rust `1.95.0` unless a repository-wide decision advances it. Make `Cargo.lock`, Cargo
workspace metadata, inference packages, and Bazel materialization agree. Acceptance:
locked metadata, fmt, check, test, and strict Clippy pass on every required assigned
platform; dependency changes update all lock/materialization truth.

### V4-H1 — Role, session, and capability boundary (`E0+E1`)

Add typed public/worker/operator messages; daemon-minted session, request capability, and
worker nonce; ownership-bound requests/receipts; pre-dispatch role rejection; digest-only
capability recording. Acceptance: ID theft, wrong session, stale worker, role confusion,
and same-UID malicious-client tests fail closed.

### V4-H2 — Bounded lifecycle, durability, and deadlines (`E0+E1`)

Separate queue/inflight/running, global/tenant/model/device limits; bound all connections
and frame I/O; actively expire deadlines; provide durable receipt index, restart recovery,
TTL, compaction, disk budget, corruption/replay rejection; bind token count, output bytes,
rolling digest, termination reason, and model/runtime/device identity. Never claim forced
termination before observed process death.

### V4-R1 — Isolated worker process foundation (`E1`)

Add worker-host and deterministic fixture-worker crates. Use inherited pipes or owner-local
UDS, one-time nonce authentication, heartbeats, crash/hang/protocol detection, drain,
process-group termination, bounded child output, generation rollover, and stale-event
rejection. Child environments are allowlisted and contain no Hepta or provider secrets
unless an exact adapter requires a scoped value.

### V4-P1 — Real local-provider adapters (`E2`)

Run Ollama and LM Studio behind the worker boundary. Require exact preinstalled model and
service inventory; retain loopback literal pinning, no redirect/proxy/download, bounded
bodies, strict JSON/SSE, semantic result/model/usage/finish checks, helper digest binding,
and explicit cancellation classification: acknowledged, unsupported-fail-closed, or
transport-disconnect-observed. A disconnect is never an ACK.

### V4-N1 — Native llama.cpp vertical slice (`E3`)

Implement the stable C ABI against one pinned llama.cpp commit and one explicit GGUF tuple.
Minimum slice: one runtime commit, model family, quantization, tokenizer/template, target
platform, real prompt, one or more real generated UTF-8 tokens, and one digest-valid
receipt. Exercise load, warm, submit, poll, cancel, drain, unload, health, stats, and bounded
memory reclamation. Wrong digests fail before load; no remote fallback exists.

### V4-C1 — Cancellation ACK and forced-kill proof (`E1`, repeated in `E2/E3`)

Represent `CancelRequested`, `CancelSent`, `CancelAcked`, and `Killed`. Queued cancellation
is immediate. Running cancellation requires observed ACK or, after a bounded grace period,
process-group termination and observed death. Forced kill rolls backend generation and
fails colocated requests closed. Cover before-first-token, mid-stream, hung-worker, crash,
and post-cancel stale-token cases.

### V4-S1 — Scheduler, leases, cache, and resources (`E0+E1+E4`)

Add bounded fair queues; revocable input, KV, and prefix leases; exact digest cache keys;
global/tenant/model/device budgets; lazy load, one bounded warm model by default, LRU
unload, and explicit drain. No lease survives cancellation or generation rollover. Keep
continuous batching disabled until single-request cancellation/isolation proofs pass.

### V4-PB1 — Product shadow bridge (`E5`)

Add typed semantic request/result contracts and opt-in product traversal through
`hepta-inferd`, while retaining the authoritative existing route. Shadow failures never
change user output; product cancellation propagates; every shadow request has a daemon
receipt; kill switch requires no schema migration; no raw persistence or Memory/KG write.

### V4-D1 — Exact-device qualification (`E4`)

Reference profiles: Linux x64 CPU, Linux arm64 CPU, macOS Intel CPU, Apple Silicon Metal,
Windows x64 CPU, and CUDA only with a named runner/driver profile. Record device/OS/RAM,
accelerator/driver, threads/context/batch, exact model tuple, and power mode. Measure cold
and warm load, p50/p95 TTFT and inter-token latency, tokens/s, peak RSS/accelerator memory,
cancel ACK/kill latency, unload reclamation, crash recovery, 30-minute soak, and disk
growth against digest-bound hard budgets.

### V4-O1 — Independent acceptance and rollout (`E6`, then `E7`)

A non-authoring operator reviews one exact descendant evidence set and verifies rollback,
kill switch, upgrade/downgrade, and receipt migration. Rollout is separately authorized at
each step: qualification-only -> admission shadow -> developer opt-in -> bounded canary ->
explicit user opt-in -> default local route. This source package cannot accept or promote
itself.

## 6. Normative test, security, and performance policy

`HEPTA_INFERENCE_TEST_MATRIX_V1.md`, the runbook, and threat model are normative. At a
minimum they cover canonical CBOR/malformed frames; peer/role/capability/session/generation
attacks; resource and disk exhaustion; deadline/process-death semantics; token/result
integrity; receipt crash consistency/recovery/TTL/compaction/corruption; child
crash/hang/cancel/kill/restart; real provider strictness; real GGUF lifecycle; scheduler
fairness/cache/lease pressure; product shadow isolation; device benchmark/soak; and operator
promotion denial.

Durable control-plane data contains only digests, sizes, counters, exact identities, and
termination metadata. Capability/session values are memory-only and never `Debug`/traced.
Receipt writes use create-new or atomic replace, restrictive permissions, file+directory
sync, replay checks, TTL, compaction, and hard disk budget.

The default route prefers the smallest qualified model satisfying task policy: `T1` 1–3B
quantized for lightweight work, `T2` 7–8B only when admitted by the device profile, `T3`
20B+ only by explicit opt-in and dedicated budget. Use GGUF mmap where supported, bounded
KV/prefix caches, lazy load, explicit unload, at most one warm model by default, and
persistent bounded IPC rather than one connection per token.

## 7. Closure definitions and gap loop

`SOURCE_COMPLETE` requires all V4 source/docs/workflows/manifests, converged Cargo+Bazel
graphs, passing exact-head E0/E1 qualification on required platforms, executable external
evidence workflows with precise prerequisite failures rather than silent skip, zero
source-owned blockers, and closed authority. It does not mean production ready.

`MODULE_CLOSED_CANDIDATE` additionally requires E2 for every supported external provider
(or explicit scope removal), one real E3 native GGUF path, E4 for every supported device,
E5 product shadow, E6 independent acceptance, zero P0/P1 blockers, and passed rollback/kill
switch. Production/promotion/release remain false pending a separate E7 action.

For every blocker: revalidate repository/branch/head/tree/workflow/prerequisites; classify
the evidence class; implement the smallest coherent change; run the narrow test and stage
aggregate; update only active V4 truth; attach exact evidence; continue until
`MODULE_CLOSED_CANDIDATE` or a truthful `BASE_DRIFT`, `BLOCKED_UPSTREAM`, `STOP_CONDITION`,
or `RESUME_REQUIRED` state. An unavailable runner, provider, model, device, or operator is
not a closed gap; source must still leave a deterministic fail-closed execution path that
can produce the missing receipt when the prerequisite is supplied.
