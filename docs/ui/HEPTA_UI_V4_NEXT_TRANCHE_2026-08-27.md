## Completed source implementation

### 1. Rust-served CSS chain

The v4 material cascade, runtime state CSS and final accessibility preferences
are deterministically composed into the stylesheet bytes consumed by the Rust
renderer. Stable content remains unblurred; chrome/transient roles and solid
fallbacks remain governed by the v4 contract.

### 2. Single Rust-served JavaScript asset

The v4 mobile/runtime controller is no longer an unbound repository side file.
`hepta-core/build.rs` now deterministically creates the only served JavaScript
asset from:

1. `apps/hepta-control-ui/control-ui.js`;
2. an exact bundle boundary marker;
3. `apps/hepta-control-ui/control-ui-v4-runtime.js`.

The build emits the bundle plus generated component/bundle SHA-256 and ETag
constants. `control_ui_static_assets.rs` embeds those generated bytes. The
Native Gateway continues to expose only `/control-ui.js`, using the generated
bundle ETag and body. There is no second runtime script route.

The build-time SHA-256 implementation is dependency-free and performs the
standard `abc` known-answer test before generating assets. This avoids Cargo
lockfile drift while keeping the served ETag bound to exact bytes.

### 3. Runtime interaction source

The bound v4 runtime controller remains network-free and local-authority-only.
It provides:

- mobile popover/sheet focus entry, cycling and restoration;
- Escape and browser-back dismissal;
- bounded history-marker ownership;
- background scroll-lock state;
- media-query transition cleanup;
- idle/loading/fresh/stale/partial/offline/error read-state projection;
- bounded evidence-digest display.

It does not add fetch, XHR, WebSocket, EventSource, mutation, provider or effect
capability.

### 4. Native source contracts

Native source includes:

- platform material intent and runtime resolution profiles;
- transparent/solid fallback selection;
- 48 logical-pixel control migration;
- 56 logical-pixel mobile stack header;
- fail-closed tests for authority and material bounds.

These remain source contracts until compiled and exercised on target systems.
No claim is made that Windows Mica/Acrylic, macOS system materials, iOS glass or
Android dynamic tonal surfaces are presently bound to real system APIs.

- a compiled `hepta-core` bundle integration test;
- `cargo check` entries for `hepta-core` and the Native Gateway;
- fixture browser qualification;
- visual receipt schema and per-target matrix;
- exact separation of source binding, compile validation, Rust runtime,
  browser fixture, served-browser and device evidence.
