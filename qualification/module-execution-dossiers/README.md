# Hepta module execution dossiers

This qualification companion deepens the forty stable module guides without creating a second global plan or duplicating canonical ownership facts. `docs/modules/MODULES.json`, `SOURCE_BINDINGS.json`, the contract/data registries, the three delivery DAGs, the readiness registry and the CNS registry remain authoritative. `TECHNICAL.md` defines the shared execution, persistence, failure, performance, NDU, learning, self-iteration, embodiment and assimilation semantics. `MODULE_DOSSIERS.json` projects those requirements into one execution-oriented record per module and adds the evidence fields that must be materialized before composition or activation.

## Read order

1. [`TECHNICAL.md`](TECHNICAL.md) — all-module execution and evolution specification.
2. [`MODULE_DOSSIERS.json`](MODULE_DOSSIERS.json) — exact 40-module execution projection.
3. [`STATUS.md`](STATUS.md) — generated closure summary.

## What the dossier closes

Each module now has one machine-checked record for its primary lane, declared source roots, CNS organ roles, execution role, runtime and state class, integration boundary, first executable proof, mandatory fault profile, target measurement profile, NDU participation, external-system assimilation responsibilities and applicable external gates.

The common receipt contract requires exact source, guide digest, source roots, entrypoints, consumer callsites, host/runtime identity, binary or artifact digest, configuration/body generation, physical state, schema/migration, single-writer fence, terminal observer, revocation source, fault results, resource measurements, fallback, rollback predecessor and external-gate disposition. `none_by_design` is valid only when the module proves the absence of the corresponding state or boundary.

## Claim boundary

A completed dossier is documentation evidence. It is not proof of source compilation, runtime attachment, real-model use, future-window efficacy, functional biomimicry, physical safety, owner consent, independent acceptance, production canary, selection, promotion or release. The nine external gates from `docs/readiness/GAPS.json` remain projected exactly and cannot be changed by this companion.

The canonical human entry point remains `docs/DEVELOPMENT.md`. Module teams continue to start from their own `docs/modules/<module>/TECHNICAL.md` guide and use `docs/readiness/PARALLEL_DEVELOPMENT.md` plus this dossier as the mandatory execution overlay.
