The planner does not call a model, persist the query, send telemetry, or perform any external effect.

## 4. Semantic candidate contract

The optional semantic batch is supplied by a qualification host. It contains no raw vectors and no memory content:

```json
{
  "query_sha256": "<exact query digest>",
  "model_sha256": "<model artifact digest>",
  "tokenizer_sha256": "<tokenizer artifact digest>",
  "index_sha256": "<index artifact digest>",
  "index_generation": 1,
  "embedding_dimensions": 768,
  "metric": "cosine_similarity_ppm",
  "batch_sha256": "<batch digest>",
  "candidates": [
    {
      "memory_id": "memory:v2:...",
      "revision": 1,
      "rank": 1,
      "similarity_ppm": 925000
    }
  ]
}
```

Validation requires:

- exact query digest equality;
- lowercase SHA-256 model/tokenizer/index/batch digests;
- positive index generation;
- 1–65,536 embedding dimensions;
- 1–32 candidates;
- contiguous ranks starting at one;
- stable memory IDs and positive revisions;
- similarity in `0..=1_000_000` ppm;
- no duplicate memory revision;
- recomputed batch digest equality.

The batch digest binds:

```text
query
model
tokenizer
index
index generation
embedding dimensions
metric
ordered candidate IDs/revisions/ranks/similarities
```

A per-candidate evidence digest additionally binds each candidate to the batch.

This proves integrity of the supplied contract. It does not prove:

```text
that an embedding model actually ran
that the index contains the claimed corpus
that vectors were generated by the bound model
that similarity is calibrated
that semantic retrieval improves task outcomes
```

Accordingly every receipt retains:

```text
semantic_host_supplied_untrusted=true
semantic_index_provenance_verified=false
local_embedding_executed=false
ann_index_executed=false
```

## 5. Candidate union and revalidation

The adapter forms a deterministic union keyed by:

```text
memory_id
memory_revision
```

Sources are:

1. the existing lexical/RRF baseline;
2. the optional semantic batch.

A semantic-only candidate is resolved through `explain_memory_head`. A lexical and semantic occurrence of the same revision must agree on content and revalidation binding or the request fails closed.

After union construction, all bindings are batch-revalidated through the existing single-snapshot `revalidate_memory_candidates` API. Stale candidates are omitted with a bounded reason code.

Candidate acquisition is not yet performed in one shared SQLite snapshot because the existing lexical baseline and host semantic resolution are separate calls. The receipt therefore states:

```text
candidate_union_single_snapshot=false
physical_send_revalidation_required=true
```

No P1.1a receipt may be attached directly at physical send without the existing final revalidation path.

## 6. Deterministic fusion

P1.1a uses fixed-point ppm signals and no floating-point state:

```text
lexical rank signal          weight 350,000
semantic similarity signal  weight 450,000
channel diversity signal    weight 100,000
temporal freshness signal   weight 100,000
```

When no semantic channel is supplied, the semantic weight is removed and the remaining weights are renormalized deterministically.

Signals are bounded to `0..=1_000_000` ppm. Sorting is deterministic:

```text
fused score descending
semantic rank ascending
lexical baseline position ascending
memory ID ascending
revision ascending
```

The output contains no memory body or source body. Each candidate receipt includes:

```text
memory ID/revision
scope
content digest
baseline position/RRF/channels
semantic rank/similarity/evidence digest
component signals
fused score
revalidation-binding digest
```

The fusion contract itself has a stable digest. Fixed weights in this source tranche are not efficacy-calibrated and cannot be promoted without a corpus-backed evaluation receipt.
